Boot OVMX in your browser

This tab boots the real OVMX runtime — the actual OVMX Linux kernel and initramfs-ovmx.cpio.gz, which loads the vms.ko VMS executive, so /dev/vms is present and DCL/RMS/RTL run against it. It is the same machine distro/boot/run-qemu.sh boots natively, running under QEMU compiled to WebAssembly — entirely client-side. Nothing here is a scripted transcript.

What this is / isn't (honest limits):
  • Real, not faked. Every character in the terminal is the guest's real serial console. Log in as SYSTEM / MANAGER (or GUEST/GUEST).
  • Slow. This is TCG (a JIT-to-WebAssembly interpreter), not KVM. Boot takes tens of seconds and interaction is sluggish. The measured boot-to-Username: time appears above once reached.
  • Single node. One tab is one VM — no cluster / SCS / multi-node behaviour here.
  • Fresh disk each load. A blank 64 MiB system disk is created in memory and installed on first boot; it is not yet persisted across reloads.
  • Needs cross-origin isolation (SharedArrayBuffer). On a host that can't set COOP/COEP headers (e.g. GitHub Pages) the self-hosted coi-serviceworker.js supplies them and reloads once.
  • Terminal styling is OVMX web-demo presentation, invented for this page — not asserted to be how VMS looked (clean-room labelling).
